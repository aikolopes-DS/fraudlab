01 — O problema Do cotidiano para os dados

Parece só
uma compra.
O modelo vê
relações.

O desafio é aprender com transações rotuladas e estimar quais têm maior risco de fraude. O modelo recebe atributos, encontra relações e produz uma pontuação entre 0 e 1.

Acertar a ordem importa: uma transação fraudulenta deve aparecer acima de uma legítima na lista de suspeitas. É isso que a ROC-AUC ajuda a medir.

Um recorte da implementação

A rede por dentro.
O método à vista.

A RealMLP usa três camadas ocultas e 16 membros no conjunto. Atributos numéricos recebem embeddings PBLD; categorias têm codificação própria. A saída combina probabilidades dos membros.

O treinamento foi executado pelo projeto com a biblioteca oficial pytabkit 1.8.0 . O código mostra a configuração completa e como os dados são separados.

  3. 03

  4. 04

    Prever fora do treino

  5. 05

    Comparar ROC-AUC e estabilidade entre divisões. Manter a autoria dos componentes externos.

  6. 06

    Competir de verdade

    Validar o arquivo, enviar as previsões e registrar a avaliação e a posição observadas.
